# swm-uws 0.8.0

Minor release: add an explicit native representation for reusable response
headers and remove the response-header validation cache that regressed the
ordinary write path.

## Prepared response headers

`PreparedHeaderBlock` copies and validates a flat array of header name/value
pairs once. `HttpResponse.endPrepared()` then writes the status, prepared block,
and optional body in one corked operation. `capabilities().preparedHeaders`
advertises the extension.

Blocks accept at most 64 pairs and 64 KiB of exact UTF-8 payload.
`Content-Length` and `Transfer-Encoding` remain binding-managed and are
rejected. The wrapper is immutable and branded per binding environment.

The block metadata, line index, and payload occupy one ArrayBuffer backing
store. V8 accounts its exact allocation size, and the backing-store deleter
only destroys C++ storage without entering an isolate.

## Header validation path

The previous one-entry V8 string cache is removed. Validation still runs for
every ordinary `writeHeader()` call. On the isolated Linux x64 Node 24 PGO host,
cacheless native ABBA/BAAB comparisons produced:

| Workload                                 | Throughput |     p99 | RSS peak | Blocks |
| ---------------------------------------- | ---------: | ------: | -------: | -----: |
| One repeated header, the cache best case |     +4.23% |  -2.93% |   +0.13% |    3/3 |
| Stable names with dynamic values         |    +16.63% | -13.81% |   +0.25% |    3/3 |
| Rotating names and dynamic values        |    +20.39% | -15.50% |   +0.32% |    3/3 |

Each block used c100/p10, 3 s warmup, 10 s measurement, server CPU 2, and load
CPUs 3-6 on an Intel Xeon E5-2680 v4. These figures isolate the native header
path and are not general application throughput claims.
