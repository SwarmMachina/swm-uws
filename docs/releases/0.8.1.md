# swm-uws 0.8.1

Patch release: correct native memory ownership and request lifetimes during
response completion, route yielding, WebSocket upgrade, and application shutdown.

## Lifecycle and memory fixes

- Closed applications release native contexts and registered handlers after
  active native callbacks return. WebSocket callbacks own their V8 handles
  directly, and failed registrations release partially constructed handlers.
- Body callbacks can upgrade fixed-length and chunked HTTP requests without
  accessing the destroyed HTTP context or callback storage.
- Yielded HTTP and upgrade routes transfer control without prematurely closing
  the response; wrappers retained by the previous route are invalidated.
- Disconnect filters retain read-only access to remote address metadata while
  rejecting writes and callback registration on the closed response.
- Completing a response while its request body is still draining preserves the
  connection timeout. Empty `tryEnd()` calls do not complete an unfinished body.
- Discarded and overflowing body collectors immediately release their buffers.
  Native loop teardown also releases deferred closed sockets.
- Request prefetch snapshots use one contiguous allocation and report the full
  backing-store size to V8.

## Validation completed during preparation

- 160/160 tests on Linux x64 / Node 22 and macOS arm64 / Node 24, including
  26 new lifecycle and memory regression scenarios.
- Raw V8 HTTP and WebSocket smoke tests, C++ quality checks, ESLint, Prettier,
  vendored-source integrity, and dependency audits passed.
- Five Linux comparisons against the v0.8.0 source baseline passed the existing
  throughput, p95/p99 latency, RSS, and error guards: HTTP, 1 KiB `collectBody`,
  `stream-begin`, materialized request prefetch, and WebSocket echo.
- WebSocket echo combined eight balanced ABBA/BAAB blocks: paired throughput
  +1.00%, median run p99 1.55 ms versus 1.61 ms, and zero transport errors.

These native Linux comparisons used four-second warmup and six-second measured
runs with separate server and load-generator CPU affinity. They describe the
measured scenarios, including the small chunked `stream-begin` response.

The release workflow rebuilds the Linux, Windows, and macOS Node 22/24 artifact
matrix, runs the PGO/LTO comparison against pinned upstream, verifies packed
consumers, and checks npm integrity and provenance before completing publication.
