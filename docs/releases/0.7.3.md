# swm-uws 0.7.3

Patch release: bound request-body delivery when the application pauses reading.

## Fix

`HttpResponse.pause()` now stops further socket receives even when the current
receive buffer was full. Previously, the receive loop could continue delivering
512 KiB blocks after pause, allowing a slow streaming consumer to queue almost
the entire upload in memory. `resume()` restores normal reading.

Callbacks may still consume HTTP chunks already present in the current parser
buffer. Applications must call `resume()` when ready for more data; an omitted
resume can no longer be masked by continued reads after pause.

No public signatures or advertised capabilities change. Buffered body collection
continues to materialize the complete body. The fix adds polling-state checks to
the shared receive loop without adding payload copies or allocations.

## Regression coverage

- Fixed-length and chunked upload pause/resume, with SHA-256 content validation.
- Client TCP FIN immediately after upload while the server applies backpressure.
- swm-core integration: bounded Readable queue at 1/16/64 MiB, concurrent uploads,
  cancellation of a paused stream, and connection reuse after draining.

## Release checks

Local preparation does not publish the package or create a release tag. The full
release workflow must validate a commit already merged into master. It builds
Node 22/24 binaries for Linux x64, Windows x64, macOS arm64 and macOS x64, assembles
the checksummed package, and tests packed consumers before publication.

The Linux candidate must pass PGO/LTO performance comparisons and the Bookworm
ABI ceilings. Raw source builds are diagnostic evidence, not substitutes for the
release artifact matrix.
