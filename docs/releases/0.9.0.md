# swm-uws 0.9.0

Add Node.js 26 support and refresh the vendored transport to uWebSockets.js
20.71.0. Node.js 22 and 24 remain supported.

## Supported native targets

| Platform    | Architecture | Node.js 22 (ABI 127) | Node.js 24 (ABI 137) | Node.js 26 (ABI 147) |
| ----------- | ------------ | -------------------- | -------------------- | -------------------- |
| Linux glibc | x64          | yes                  | yes                  | yes                  |
| Windows     | x64          | yes                  | yes                  | yes                  |
| macOS       | arm64        | yes                  | yes                  | yes                  |
| macOS       | x64          | yes                  | yes                  | yes                  |

The release contains 12 native binaries. Installation does not compile native
code. Linux musl, Linux arm64, Windows arm64, TLS, HTTP/3, and WebSocket
compression remain unsupported.

## Changes

- Adapt module initialization and WebSocket property-descriptor copying to
  Node.js 26's V8 API.
- Remove intermediate collection allocations for complete single-chunk request
  bodies and keep collector state inside the asynchronous response. The final
  ArrayBuffer owns its copied bytes; fragmented collection, limits, and abort
  handling retain their existing behavior.
- Avoid repeated internal-field bounds checks on HTTP paths after receiver
  validation or on native-owned template clones. Expand forged-receiver
  coverage for response completion, abort handlers, and body collection.
- Reduce WebSocket callback GC pressure and receiver-validation overhead on
  Node.js 26. Temporary callback buffers remain protected against JavaScript
  transfer, and forged or closed socket receivers still fail before native use.
- Avoid string-arena bookkeeping for binary payloads and hide internal Linux
  symbols so LTO can optimize calls across binding modules. Nested header
  strings retain their storage through batched response completion.
- Create copied bodies directly in their final ArrayBuffer and cover owned-body
  transfer after application shutdown and GC.
- Track uWebSockets.js 20.71.0 and its exact uWebSockets/uSockets source revisions.
  Adopt upstream complete chunk emission and Host/header validation while
  preserving the binding's strict request framing, timeout policy, and HTTP
  error contracts.
- Rebase the interdependent local security/lifecycle patches into one
  reproducible cumulative patch; retain the existing uSockets patches.
- Match the manual collector benchmark reference to the owned ArrayBuffer
  contract using standalone backing stores. Test exact size, transfer, and
  retained payloads independently of Node.js Buffer pooling; guard thresholds
  remain unchanged.
- Extend build, artifact verification, installed-package, performance, and
  consumer CI matrices to Node.js 26. Performance evidence reads the pinned
  upstream tag generically and rejects a mismatched reference version before
  collecting measurements.
- Refresh vulnerable development-tool dependencies and pin the fixed minimatch
  release until the upstream ESLint dependency range advances. Runtime
  dependencies remain zero.
- Support npm 11 and npm 12 pack metadata formats. Reference installation
  explicitly permits the pinned Git dependency and uses the working upstream
  CommonJS entrypoint because this upstream release's ESM wrapper imports a
  missing file. Feature benchmarks normalize the complete binding API before
  application setup and socket-helper calls; startup/HTTP/shutdown tests cover
  both ESM and CommonJS bindings.

The experimental upstream microcache overload of `get()` is not supported;
route registration still requires exactly a path and handler.

## Validation during preparation

On macOS arm64, the full runtime suite passed on Node.js 22.18.0, 24.21.0,
and 26.13.0, along with HTTP/WebSocket smoke and runtime API comparison against
commit-pinned uWebSockets.js 20.71.0. Packed consumer declarations and package
metadata checks passed with npm 11 and 12. An installed Node.js 26 package
passed without a build fallback.

C++ static checks, JavaScript lint/format checks, vendored-source checksums,
byte-for-byte patch replay, and ASan/UBSan parser fuzzing passed. See the
[research and validation record](../research/2026-11-03-node26-uws.md) for exact
versions and limitations.

The release candidate must additionally pass the complete CI matrix, Linux
PGO/LTO performance qualification, packed consumers, and all artifact digest
checks. A master-branch workflow dispatch builds and tests a candidate without
publishing; publishing requires the matching version tag and successful gates.
