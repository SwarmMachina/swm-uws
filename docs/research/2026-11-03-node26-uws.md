# Node.js 26 and uWebSockets update

Primary sources checked on 2026-11-03. This note records upstream evidence and
integration implications; validation results belong to the implementation work.

## Node.js

- The official download page lists **26.13.0**, released on **2026-10-28** as
  **Lithium LTS**. The release changes LTS metadata relative to 26.12.1 and
  receives updates through April 2029. Linux official binaries have required
  `libatomic` since Node.js 25. Sources: [downloads](https://nodejs.org/en/download/),
  [26.13.0 release](https://nodejs.org/en/blog/release/v26.13.0).
- Node.js 26 uses **native module ABI 147**. The version header states that
  incompatible native ABIs cannot be loaded and that the ABI remains stable
  within a major line. A separate `node-v147.node` build is therefore required
  for each supported platform. Source:
  [26.13.0 version header](https://github.com/nodejs/node/blob/v26.13.0/src/node_version.h).
- Node.js 26.13.0 contains **V8 14.6.202.34**. Node.js 26.0.0 introduced V8 14.6,
  Temporal enabled by default, and Undici 8.0. Sources:
  [V8 version header](https://github.com/nodejs/node/blob/v26.13.0/deps/v8/include/v8-version.h),
  [26.0.0 release](https://nodejs.org/en/blog/release/v26.0.0).
- The owning release schedule identifies Node.js 22 and 24 as Maintenance LTS,
  Node.js 26 as Active LTS, and Node.js 27 as Alpha. Supporting 22/24/26 matches
  the current stable LTS lines. Source:
  [Node.js Release Working Group](https://github.com/nodejs/Release#release-schedule).

## Integration implications from source comparison

The [exact core delta](https://github.com/uNetworking/uWebSockets/compare/fe7c01a477b688a7743f754fee33bdd78d52ad91...1d80f7a53816ef2433e89793b285b827f3efb2b2)
fixes `beginWrite()` chunk framing, guards publishing without a WebSocket
context, validates Host/header syntax more strictly, and changes chunk parsing.
It adds `HttpCache.h` and makes `TemplatedApp` inherit its overloaded `get`.
Consequently, local framing patches need rebasing or removal where superseded,
and member-function pointers may need an explicit overload cast.

The updated upstream parser still allows identical duplicate Content-Length
fields and Transfer-Encoding values ending in `chunked`. The project's existing
patches intentionally reject duplicate framing fields and accept only a single
`chunked` coding. Preserve those documented guarantees while refreshing vendor
sources, and rerun raw HTTP, parser fragmentation, lifecycle, and backpressure
checks. The existing local hardened chunk parser must be reconciled with the
upstream replacement rather than overwritten by it. Source:
[same core delta](https://github.com/uNetworking/uWebSockets/compare/fe7c01a477b688a7743f754fee33bdd78d52ad91...1d80f7a53816ef2433e89793b285b827f3efb2b2),
local `vendor/PATCHES.md`.

Adding Node.js 26 requires the engine range, ABI-based loader resolution, release artifact
manifest, build scripts, CI build/test/package matrices, documentation, and
packed-consumer coverage to agree on ABI 147. Linux, Windows, macOS arm64, and
macOS x64 binaries require their respective native build environments; a local
macOS test does not establish the other platforms' runtime behavior.

## Implementation and local validation

The implementation now pins uWebSockets.js 20.71.0 and supports Node.js
22/24/26 in package metadata, native builds, release manifests, build matrices,
packed-package smoke matrices, and the consumer matrix. ABI 147 is required
on all four supported platform/architecture targets; release assembly requires
12 artifacts instead of eight.

The existing security and lifecycle changes were rebased into
`vendor/patches/uwebsockets-local-policy.patch`. The stricter local chunk decoder
and duplicate framing rejection remain. Upstream chunk emission replaces the
old beginWrite state-bit workaround. The new header-defined cache clock helper
is marked inline for multi-translation-unit builds. Experimental JavaScript
microcaching remains unsupported and its extra route argument is rejected.
The V8 adaptation passes the isolate explicitly through WebSocket descriptor
helpers and obtains the current isolate at module initialization.

Validated on macOS arm64:

| Node.js 22.18.0 | 170/170 full tests, HTTP/WebSocket smoke, upstream surface comparison; two later npm-format regression cases passed in the focused helper suite                                                         |
| Node.js 24.21.0 | 172/172 full tests, HTTP/WebSocket smoke, upstream surface comparison                                                                                                                                   |
| Node.js 26.13.0 | 170/170 full tests, HTTP/WebSocket smoke, upstream surface comparison; two later npm-format regression cases passed in the focused helper suite; clean installed-package smoke without a build fallback |

Packed consumer declarations and package metadata checks passed on Node.js
24.21.0/npm 12.1.0 and Node.js 26.13.0/npm 11.20.0. The package tooling accepts
both the array and package-name-map forms observed from `npm pack --json`.
The commit-pinned reference installation explicitly permits its Git dependency
for npm 12 and was tested with scripts disabled. Performance evidence reads the
release commit from the current vendor table, checks its tag against package
metadata, and rejects a differently versioned reference before reading raw
measurements. Regression coverage includes future tag values and stale,
duplicate, malformed, and missing release metadata.

C++ formatting/static analysis passed for 37 source files and 19 translation
units against Node.js 26 headers. JavaScript lint, Prettier, vendor integrity,
byte-for-byte clean patch replay, generated benchmark report validation, and
matrix consistency checks passed. Parser fuzzing completed 1,158,822 runs in
16 seconds with ASan/UBSan and no findings; leak detection is disabled by the
existing macOS harness.

This is local source validation. Linux/Windows/macOS x64 builds, Linux PGO and

not regenerated. No package publication or deployment was performed. Locally

## Release 0.9.0 preparation

The release candidate bumps package/lockfile metadata to 0.9.0 and documents
all 12 platform/ABI targets in `docs/releases/0.9.0.md`. After refreshing the
compatible dev-tool dependency graph, the strict production/development audit
reported zero vulnerabilities. A temporary `minimatch` 11.0.4 override resolves
the advisory affecting ESLint's older dependency range; no runtime dependency
was introduced. Advisory source:
[GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249).

With the refreshed tools and package version, Node.js 24.21.0 on macOS arm64
passed all 172 tests, HTTP/WebSocket smoke, pinned upstream comparison, packed
types/package checks, vendor integrity, lint/format checks, and generated report
validation. Full CI remains the authority for the release artifact matrix.

The feature-benchmark child process normalizes the imported binding once,
including shared local-port and listen-socket-close helpers. A real native
CommonJS bridge regression test reproduced the prior namespace/default mismatch
before the fix, and verifies successful IPC readiness, HTTP handling, and a
zero-exit shutdown after the fix. All five feature paths passed short functional
runs against the official CommonJS reference with the CI pipelining settings;
these short runs are functional validation, not performance qualification.

A separate macOS arm64 preflight of pinned swm-core 5.0.3 passed all 66 E2E
cases on Node.js 26.13.0 using its actual CI-produced ABI-147 candidate binary.
The consumer's old Node.js engine declaration produced a warning with the pinned
pnpm 11.20.0, without blocking installation or build. The complete CI consumer
matrix remains required for release acceptance.

The first complete performance run on source commit `795ad4a` passed Node.js 22,
but the Node.js 24 POST-4096 collection scenario failed its unchanged -5%
throughput guard in both independent builds (-5.53% and -6.01%). Other HTTP
features, raw HTTP, WebSocket, latency, and RSS guards passed. A reduced real
Node.js 24.19.0 replay on the same host reproduced the throughput failure;
short samples also showed enough noise to require full six-block measurements.

Changing only the final vector-backed buffer to a V8-managed copy did not help
and was discarded. The retained change copies a complete, single-chunk body
straight into its final V8 backing store, without an intermediate vector, and
stores BodyCollection inside AsyncResponseState instead of allocating it
separately. V8 13+ can skip zero-initialization because every byte is copied
before the ArrayBuffer becomes visible; Node.js 22 uses its compatible API.
Fragmented bodies retain the existing bounded vector/ownership path. The
lifetime regression now retains both complete 4096-byte and fragmented 64-KiB
bodies across application shutdown and GC, for both collection methods.

The final prototype passed all 177 runtime tests and HTTP/WebSocket smoke on
macOS arm64 with Node.js 22.18.0, 24.21.0, and 26.13.0. A full six-block Linux
POST-4096 prototype replay passed the unchanged throughput, latency, and RSS
guards twice (paired throughput differences -1.13% and -2.44%).
This diagnostic prototype reused an earlier PGO profile and is not release
qualification: the final CI must retrain and qualify both independent binaries
for every supported Node.js major before acceptance.

## Performance follow-up (2026-11-04)

The complete matrix on `f116633` passed Node.js 22 qualification. The remaining
failures exposed separate limits: Node.js 24 passed POST throughput but failed
one POST p95 and one WebSocket depth-16 guard; Node.js 26 failed depth-16
throughput in both independent builds (-10.66% and -9.37%). The macOS arm64
Node.js 26 job never acquired a hosted runner, so it executed no source checks.
See [CI evidence](https://github.com/SwarmMachina/swm-uws/actions/runs/41693892446).

A reduced real WS-16 replay reproduced the Node.js 26 regression. CPU profiles
showed additional receiver-validation and temporary-buffer/GC work. V8 stores
each detach key in a Cell allocated in old space: using the buffer itself as
that key adds an old-to-young reference. A non-undefined null key keeps the
JavaScript detach lock without that reference. The scope receives its isolate
explicitly and retains the matching key for native detachment. Primary source:
[SetDetachKey](https://github.com/nodejs/node/blob/v26.13.0/deps/v8/src/objects/js-array-buffer.cc),
[NewCell](https://github.com/nodejs/node/blob/v26.13.0/deps/v8/src/heap/factory.cc).

WebSocket callbacks now carry a unique per-template Symbol receiver token.
Bounds and token equality are checked before the native state pointer is read.
The original raw kind tag is retained, with null pointer slots for generic
request/response guards, so cross-kind calls still reject safely. Tests cover
request/response/snapshot methods borrowed onto sockets, forged prototype or
Proxy receivers, transfer rejection, and callback-end detachment.

The original full WS protocol passed on the prototype: six ABBA/BAAB blocks,
both depths, the same Node.js 24 driver and Node.js 26 target, and unchanged
5% throughput and telemetry rules. Paired differences were -2.45% at depth 1
and -2.83% at depth 16. These measurements reused an earlier PGO profile;
the final source must be retrained and qualified in CI.

Copied bodies also use the direct ArrayBuffer allocation API, removing an
extra allocation boundary before the final copy. A full six-block POST-4096
replay passed throughput, p95, p99, and RSS guards (-0.42% paired throughput).
Owned-body lifetime coverage now transfers complete and fragmented collected
bodies after application shutdown and GC. The final source passed all 177
runtime tests and HTTP/WebSocket smoke on macOS arm64 with Node.js 22.18.0,
24.21.0, and 26.13.0.

Additional ArrayBuffer `transfer`/`transferToFixedLength` probes run on V8 13+.
The same probe aborts inside V8 12's ArrayBufferTransfer on Node.js 22.18.0
with the original self-key binding as well as the new key. This is an existing
runtime limitation; the structuredClone lock and native callback-end detachment
checks remain enabled on every supported runtime.

A fresh balanced PGO rebuild of the final source on the Linux diagnostic host
passed POST-4096 throughput, p95, p99, and RSS guards (+1.94% paired throughput).
The full WS replay passed depth 16 (-1.41%) but narrowly failed depth 1
(-5.06%, against the unchanged -5% limit). Individual pairs varied widely.
These host-toolchain measurements do not qualify the release; the complete
Bookworm CI must build and check both independent binaries on all three majors.

## Node.js 24 POST-4096 follow-up (2026-11-04)

[CI on 3d97591](https://github.com/SwarmMachina/swm-uws/actions/runs/41735599578)
passed all 12 native targets and both independent performance qualifications
on Node.js 22 and 26. Node.js 24 failed only the first binary's POST-4096
throughput guard (-5.34%, against the unchanged -5% limit); its second binary
passed at -4.74%. Both binaries passed the other feature and WebSocket guards.

Replays used the exact failed binary and Node.js 24.19.0 on the same host.
The short replay passed at -3.50%; full six-block replays passed at -4.47%
and -3.56%. This is a variable threshold crossing with persistent overhead,
so repeating CI alone would not establish useful performance margin.

Paired CPU profiles attributed 3.61% of candidate samples to
`v8::Object::InternalFieldCount`, with further related V8 header work.
Memory-copy samples were comparable (10.45% candidate, 10.61% upstream).
Native HTTP paths repeatedly checked layouts after validating the Response
brand, or while accessing binding-owned request/response template clones.
The optimization reuses that validation for pointer access at those specific
sites. The public receiver brand guard, closed/read-only response checks,
metadata ownership, and callback invalidation still run. Security coverage
now exercises end, abort registration, and collection on plain objects,
other binding objects, forged prototypes, and Proxy receivers.

A controlled six-block native/native comparison used the same compiler,
Node.js headers, and original PGO profile for both source variants. Both
sides executed the collector helper. Removing the redundant checks improved
paired throughput by 2.64%, winning five of six pairs (IQR +0.66% to +3.30%).
This isolates the code change but does not replace fresh PGO qualification.
The final source passed all 177 runtime tests and HTTP/WebSocket smoke on
macOS arm64 with Node.js 22.18.0, 24.21.0, and 26.13.0, plus the C++ quality
gate on Node.js 26 headers and JavaScript lint/format checks.

The original pooled-reference POST replay on the freshly retrained Node.js 24
binary passed throughput (+1.67%) but failed p95 (9.129 ms versus 8.806 ms).
Investigation found a benchmark contract mismatch: Node.js 24.19.0 uses a
64-KiB Buffer pool, and Buffer.allocUnsafe(4096) returns a view into that pool.
The collector API instead promises independently owned ArrayBuffer bodies.
Measured pooled backing-store size was 65536 bytes for both 256- and 4096-byte
bodies; its pool is marked untransferable. Primary source:
[Node.js 24.19.0 buffer implementation](https://github.com/nodejs/node/blob/v24.19.0/lib/buffer.js#L168).

A real POST-through-adapter regression failed before the correction, reporting
65536-byte backing stores instead of the requested 256/4096 bytes. The manual
reference now uses Buffer.allocUnsafeSlow to own exact-size, transferable
backing stores. The same regression then passed, including transfer and payload
integrity, on Node.js 22, 24, and 26. New collector benchmark artifacts record
bodyOwnership=exact-size-transferable. The five feature paths, ABBA/BAAB
schedule, runtime/reference pins, load, and throughput/latency/RSS thresholds
are unchanged. Earlier pooled-view measurements above remain historical
evidence and must not be described as equivalent ownership qualification.

The exploratory V8 multi-field setter change was discarded; only the measured
redundant-check optimization is retained in the native implementation.

The freshly retrained final native binary then passed the complete six-block
POST-4096 protocol against the ownership-matched reference: +18.15% paired
throughput, with p95, p99, and RSS guards all passing. This comparison uses
standalone bodies on both sides; it is not a claim of the same speedup against
the earlier pooled-view workload. Final acceptance still requires both
independent Bookworm builds on all three supported Node.js majors in CI.

The final expanded suite passed all 179 tests and HTTP/WebSocket smoke on
macOS arm64 with Node.js 22.18.0, 24.21.0, and 26.13.0. Each major was rebuilt
with matching headers before its suite, including tests that load build/Release
directly. The generated historical benchmark report remains unchanged; new
collector reports explicitly label the standalone owned-body reference.

## 2026-11-05: release-tag WebSocket qualification

[Tag workflow 41916564531](https://github.com/SwarmMachina/swm-uws/actions/runs/41916564531)
passed every native build and the Node.js 22/24 performance gates. Its first
Node.js 26 binary failed the valid WS depth-16 guard at -5.71%; the second
passed at -2.94%. Both retained all 48 rows, and every HTTP/feature guard passed.
The publish job was skipped.

The exact first binary, Node.js 26.13.0 target, Node.js 24.19.0 driver, and
commit-pinned upstream binary were replayed on 155. The unchanged WS protocol
failed again: -6.81% at depth 16, while depth 1 passed at -1.21%. A control
rebuild in the pinned Bookworm image with Clang 18.1.8 and the original training
profile was byte-identical to the failed CI binary
(`2aa193990e36a3a9e8d7c42008c6ce72f21849a2f3c3095d84e7dc458f1d57bb`).

CPU profiles showed unnecessary thread-local string-arena bookkeeping inside
binary NativeBytes conversions. Arena leases now start only for strings and
are released only by an instance that acquired one. The required endBatch
status string keeps nested header views alive; binary backing-store ownership
is unchanged. A wire test covers retained UTF-8 headers across alternating
binary and UTF-8 body conversions.

Reusing the old profile after this change still failed at -5.44%. A complete
fresh balanced PGO build then passed depth 16 at -4.86%, with a narrow margin.
Linux internal-symbol visibility was therefore tested separately using this
fresh profile. It reduced exported swm symbols from 242 to zero while preserving
all 180 runtime checks and HTTP/WebSocket smoke. On an idle host, the full WS
protocol passed at -3.25% for depth 16 (IQR -4.28% to -2.21%); all six paired
deltas met the unchanged -5% budget. Depth 1 passed at -2.13%.

A preceding visibility experiment during renewed MongoDB load failed at
-5.11%; it remains recorded. The host probe showed 6.77 MongoDB CPU cores and

total use before the idle comparison. The busy trial does not isolate the

The arena change passed all 180 tests plus HTTP/WebSocket and raw V8 smoke on
macOS arm64 with Node.js 22.18.0, 24.21.0, and 26.13.0. C++ checks passed for
